# Host generation from kernel contracts (`amdc gen-host`)

Route-B P5(b)+(c), zero unsafe on the Rust side. The kernel's own `Function` is the single source of
truth: the generator reads `Function.args` (kernarg byte offset / size / type), the declared
`Contract` (`arg_tensor` extents, `ka_is`, `ka_range`, `ka_one_of`, `grid_is`, `sym_ranges`) and the
kernel metadata (`kernarg_size`, `workgroup_size`, `lds_bytes`, `compile_profile`). It emits a C++
header and JSON for host launchers; nothing in the header was copied by hand from `ref_host.cpp`.

## Usage

```bash
# one kernel
bash tools/container/cargo.sh run -q --bin amdc -- gen-host fmha_fwd_hd128_mxfp8_v3_vs128 --out build/hostgen

# every shipped v3 kernel
bash tools/container/cargo.sh run -q --bin amdc -- gen-host --shipped --out tests/gpu/generated
```

Per kernel `<kernel>_abi.h` / `<kernel>_abi.json` are written; `--shipped` also writes
`shipped_abi.h` (includes all four) and `shipped_abi.json` (array). The files committed under
`tests/gpu/generated/` are the current generated artifacts; regenerate after changing a kernel's ABI
or contract and commit them together.

## Generated C++ header

Namespace `amdc_hostgen::<kernel>`:

- `struct Args` — packed (`#pragma pack(1)`) kernarg struct, one named field per declared argument,
  byte-exact `static_assert(offsetof(Args, field) == ...)` and
  `static_assert(sizeof(Args::field) == ...)`, plus `static_assert(sizeof(Args) == kernarg_size)`.
  The generator refuses overlapping/duplicate arguments.
- `struct Symbols` — every free symbol appearing in an extent/grid/`ka_is`/`sym_ranges` relation,
  defaulted to its contract lower bound (`KL=0`, all others `1`); host sets the real values.
- `struct BufferSizes` — one `uint64_t` per pointer argument with an `arg_tensor` extent.
- `ka_at(Args, offset)` — typed kernarg scalar reader (all scalar byte offsets the contract uses).
- `validate(const Args&, const BufferSizes&, dim3 grid, const Symbols&, std::string* err)` — evaluates
  every host-checkable contract before launch:
  - `arg_tensor.alloc` → `sizes.arg >= eval(alloc)` (`logical` slack is not required for allocation);
  - `ka_range` / `ka_one_of` / `ka_is` on every referenced offset;
  - `grid_is(axis)` vs the supplied launch grid;
  - `sym_ranges` bounds;
  returns `false` with a `GV-HOST-*` code/message on the first failure.
- `launch(hipFunction_t, const Args&, dim3 grid, dim3 block, size_t lds = 0, hipStream_t)` —
  `hipModuleLaunchKernel` with `HIP_LAUNCH_PARAM_BUFFER_POINTER` over `Args`. **`lds` defaults to 0**:
  the DSL's LDS is a kernel *static* group segment (`LDS_BYTES` is emitted as metadata, not passed as
  dynamic shared memory). Passing `LDS_BYTES` here is wrong and causes
  `HSA_STATUS_ERROR_INVALID_ALLOCATION` (found during the ref_host switch).
- `block()` and, when every grid axis has a `grid_is`, `grid(Args, Symbols)`.

The `Args` buffer must stay alive until the kernel **completes**; HIP may not copy the kernarg buffer
at launch. `ref_host.cpp` therefore keeps the generated bytes in its main-scope `args`/`cargs`
buffers rather than a temporary.

## JSON metadata

`_abi.json` repeats the same facts without C++/HIP dependencies: `kernel`, `kernarg_size`,
`workgroup_size`, `lds_bytes`, `compile_profile`, `args[]` (`name/offset/size/type`), `extents[]`
(`arg/alloc/logical` as contract expressions), `ka_is[]`, `ka_range[]`, `ka_one_of[]`, `grid_is[]`,
`symbols[]` (`name/lo`). It is intended for Python/aiter loaders and for diffing ABI changes in CI.

## ref_host.cpp integration

`tests/gpu/ref_host.cpp` includes `generated/shipped_abi.h`. For the shipped v3 kernels
(`fmha_fwd_hd128_mxfp8_v3_{vs128,t128,kvsplit,kvsplit_combine8h}`) it:

1. builds the generated typed `Args` from the same shape values (the bytes are compared to the old
   hand ABI by `contract_host_truth`);
2. fills `BufferSizes`/`Symbols` and calls generated `validate` before **every** launch, aborting with
   the generated error if a contract is violated;
3. calls generated `launch`, including the generated grid/block helpers where available.

The vendor kernel and legacy/dsl/env-override kernels keep the historical hand path. Set
`REF_GEN_ABI_OFF=1` to run the old hand-only path for A/B; both paths were compared on GPU 7.

## Scope and limitations

- Host-checkable contracts only. Tile lifetime/protocol and kernel-side proofs remain `gpu_verify`;
  the generated `validate` does not replace the verifier.
- Scalar/argument **values** for the shipped kernels are still assembled in `ref_host.cpp` and then
  copied into the generated `Args`; the generated struct/offset assertions, `validate` and `launch`
  are authoritative. Moving the remaining value assignments to named generated fields is mechanical
  follow-up (the ABI itself is no longer hand-maintained).
- The header uses the HIP runtime for `launch`; it is host C++, not Rust unsafe. Every Rust crate
  keeps `#![forbid(unsafe_code)]`.
- `--shipped` currently names the four v3 FMHA kernels; other kernels can be passed explicitly.
- Kernel-side `lds_bytes` is static LDS metadata; only pass a non-zero `launch` `lds` for a future
  dynamic-shared-memory kernel.
