# W3 B5 / B6: cross-iteration scheduling and schedule-aware register allocation (design note)

The back-end Weaver steps B5 and B6 of [`two-weavers-plan.md`](two-weavers-plan.md), designed together because they meet in the same loops: a
cross-iteration order (B5) changes which values are live together, and a register plan (B6) limits which orders are possible. Context:
[`two-weavers.md`](two-weavers.md) (plan types, section 3), B3 / B4 in `crates/amdgpu-codegen/src/bweave.rs`, the replica findings in
[`fmha-replica.md`](fmha-replica.md) sections 4.4, 4.7 and 4.8.

Rules as for every W3 step: opt-in (plan-driven or a lowering token), md5-identical when a plan does not ask for it, behaviour changes gated by
`tools/perf_ab.sh` + `tools/port_gate.sh` (no family slower beyond noise), correctness by gpu_verify, the hazard oracle and the hardware gates.

## 1. Targets

| step | first target | what it must produce | today |
|---|---|---|---|
| B5 | replica copy ring (fmha-replica.md 4.7 "copy issue point") | the 5 LDS-DMA issues of tile t+2 between consecutive QK MFMAs of tile t; completion before tile t+2's reads | the next tile's issues at the start of the VALU phase, each behind its own M0 write |
| B6 | replica register roles (4.4 / 4.8) | Q / S / O pinned, K / V fragments rotating through a fixed block, P reusing S, everything else allocated around them, the schedule still found | pins degrade our schedule; S + O pinned makes the scheduler fall back |

## 2. What the plan must carry

All types exist on Main (`amdgpu-dsl/src/plan.rs`); B5 / B6 add no new plan type, only meaning:

| plan item | B5 | B6 |
|---|---|---|
| `PhaseKind::LoopBody { trip, peel }` | the loop the order spans; peeled prologue / epilogue stay the front end's (`rotate`) | - |
| `UnitDecl::iter` | the iteration offset of a unit in the steady body (DMA of t+2: `iter = 2`) | - |
| `RingDecl { slots, producer_phase, consumer_phase }` | slot-reuse legality: a producer of iteration t+d writes slot (t+d) mod S; it may issue only after every read of that slot by iterations <= t+d-S completed | - |
| `SyncRule::Counted { counter, slack }` | the counted wait the reuse needs (lgkmcnt for the LDS reads of the slot, vmcnt for the DMA before its consumer) | - |
| `Phase::order = Free` + `Hints::interleave` | where the moved units go (B4's merge: DMA units as fillers of the QK skeleton) | - |
| `Phase::budget { vgpr, agpr }` | - | the per-phase register cap the scheduler and the allocator honour |
| `HandOff { via: Reg { pin, dwords, align } }` | - | values crossing phases in fixed registers |
| `RegConstraint::{Pin, RegRing, Share, Separate}` | - | the register plan (PinV, the fragment rotation, P in S) |

The front end (kernel-opt for the replica) states the ring depth (K 2 / V 3 slots, distance 2), the DMA units with their `iter`, the Free phase
and the hint; B5 does not invent a pipeline depth.

## 3. B5: cross-iteration placement in a LoopBody phase

**Mechanism.** The steady body already contains every unit of one iteration (the front end's rotation). B5 places units with `iter != 0`
inside the steady body by the B4 merge (filler units spread over the skeleton's MFMAs). What B5 adds over B4:
1. **Ring legality** (new check, `bweave::ring_check`): for every moved producer unit of ring R with offset d, the slot it writes,
   (t+d) mod S, must not be read by any consumer instruction of the same body that is placed after it, and every read of that slot by an
   earlier iteration must be ordered before it by a counted wait. Unit tags give the iteration of every instruction; the slot index is the
   unit's ring slot (static slots in the replica). A violation keeps the authored order and is reported.
2. **Waits by dependence, not by region end**: the scheduled path's waitcnt-recompute already counts per dependence. For LDS-DMA, the
   dependence "DMA of slot s completes before the first read of slot s" is a vmcnt dependence the recompute does not see (no register
   connects them). B5 makes it explicit: the producer / consumer pair of a ring is a memory dependence of the wait pass (vmcnt before the
   first consumer read, then the barrier the plan's `SyncRule::Barrier` names).
3. **M0**: each moved DMA keeps its M0 write; M0 planning (B2) merges them later. Until then a moved DMA costs its `s_mov m0` + nop.

**Out of scope for B5 v1:** modulo scheduling that changes the trip count or creates new prologue / epilogue copies. The front end keeps
`rotate`; B5 only moves units inside the steady body across declared iteration offsets.

**Gates.** md5-identical without `iter != 0` units in a Free phase. On the replica: port_gate (all sections, STRESS included: ring reuse is
exactly what a stress run catches), perf_ab fmha_mxfp8. A mutation test: a ring with one slot too few must be rejected by `ring_check`.

## 4. B6: schedule-aware register allocation

Today: lowering, then the list scheduler (pressure-aware against one `max_vgprs`), then the allocator (`regalloc.rs`, two-phase linear scan
with `regplan.rs` pins / shares / separate groups / rings / region caps), with a fallback to the unscheduled order when the allocation fails.
The failure modes measured on the replica (4.4): pins take registers the scheduler's pressure model did not know about; the fallback discards
the whole schedule.

**B6 in three opt-in parts:**
1. **B6a, budgets into the scheduler.** `Phase::budget` becomes the pressure limit of the list scheduler inside that phase (the region
   `limit=` token already does this per region; B6a reads it from the plan), and the pinned / hand-off registers of the phase are subtracted
   from the limit before scheduling. Pins then cost what they cost in the schedule, not in a failed allocation.
2. **B6b, the fragment rotation.** `RegConstraint::RegRing { bufs }` assigns successive iterations' fragments to successive buffers of a fixed
   block (the vendor's K / V in `v[20:51]`): the allocator places the ring block first (with the pins), and the scheduler sees the buffers as
   distinct registers, so a read for the next MFMA never waits on the previous MFMA's operands (the WAR the replica's authored order paid in 4.8).
3. **B6c, per-phase fallback.** When the allocation fails, the feedback names the phase over budget; the retry ladder lowers that phase's
   hoisting / unrolling only (today: the whole kernel falls back). The rest keeps its schedule.

**Interaction with B5.** B5 moves DMA units, which hold no fragment registers (LDS-DMA writes LDS), so the two compose: B5 changes the issue
points, B6 the registers. The V prefetch (4.7) moves fragment reads across the barrier and therefore needs B6b's rotation to pay off.

**Gates.** md5-identical without budgets / rings / pins in the plan (today's kernels keep `regplan` as is). On the replica with `pin_roles`:
port_gate + perf_ab, against the unpinned replica (the user rule: no drop). A check that the allocator honours every `RegConstraint` exists
(`regplan` verification); B6 adds a check that every phase's footprint is within its budget (the region-cap check, keyed on phases).

## 5. Order of work

1. B5 ring check + the LDS-DMA wait dependence (md5-identical; unit tests with a synthetic ring; a mutation test).
2. B6a budgets into the scheduler (md5-identical; tests).
3. kernel-opt: the replica plan with the distance-2 ring (Free phase, DMA fillers with `iter = 2`), measured with B5 on.
4. B6b rotation + B6c per-phase fallback; kernel-opt: `pin_roles` on the replica with the full register plan, measured with B6 on.
