# 性能矩阵：出厂 FMHA / GEMM 对厂商内核（同一次运行、交替测量）

Main `f2759cd`，MI355X（mi355-gpu-53，**GPU 4**），2026-11-05。脚本：`tools/perf_matrix.sh`（原始输出）+ `tools/perf_matrix_md.py`（表格）；
原始逐次数据见 `docs/perf-matrix-raw.txt`。

## 方法

* **硬件 / 时钟**：单卡 GPU 4；**未锁频**（功耗墙下的自然时钟，满载约 2.0–2.1 GHz）。kernel-opt 可能同时在 GPU 5 上跑任务（同板功耗共享），所以绝对值有 ±1–2 % 的运行间漂移，
  比值比绝对值更可靠。
* **交替（interleaving）**：每一次 `ref_host` / `gemm_ref_host` 进程里厂商内核与我们的内核在同一个进程、同一组输入上依次计时（先热身，再各 100 次启动取均值）；
  **重复轮在外层、形状在内层**（5 轮 × 全部形状），所以时钟漂移被均摊到所有形状。每格取 **5 次的中位数**，比值 = 我们的中位数 / 厂商的中位数。
* **FMHA**：热身 150 + 100 次计时（`REF_WARMUP=150 REF_ITERS=100`），`REF_ROWS=1`；`auto` 分发由 `ref_host` 按形状选择，"路径"列是它实际选的内核
  （`t128` = 128 行/块，`vs128` = 256 行/块，`kvsplit` = KV 分裂主核 + combine，计时为 main+combine 的总时间）。TF/s 按 4·B·H·S·SK·128 计算。
* **FMHA 精度**：每个形状另跑一次 `REF_ROWS=64`（64 行 × 128 维对 CPU 模型）：`bad` = 超出绝对容差的元素个数，`mean_err` = 平均误差。ours 与 vendor 的 `bad` 同为非零时
  （8192/4096 等 `vs128` 形状上两者逐位相同，如 4/4、3/3）是容差处的并列，不是回归；`vs128` 用厂商配方（`vref`）所以数值与厂商一致，`t128` / `kvsplit` 的 mean_err 约为厂商的 1/3。
* **GEMM**：每个形状 5 个进程，每个进程 `REF_REPS=3` × 100 次启动（热身 300）取中位数，再取 5 个进程的中位数；每个进程都做 48 行 × 全部列的双精度 CPU 校验（`GEMM_OK`）。
  形状均满足 M、N 为 256 的倍数、K 为 128 的倍数且 ≤ 8192。

## 摘要

* FMHA：25 个形状比值范围 **0.816 – 1.300**，几何平均 **1.000**。小/中形状（`t128` / `kvsplit`）多数 ≥ 1.0（B1H8S2048 `kvsplit` 1.30×）；
  大形状（`vs128`，每 CU 满载）为 **0.88–0.93×**（见 `docs/current-status.md` 的 `vs128` 对比）；最差点是 B8H8S1024 `vs128` 0.816×。
* GEMM：6 个形状比值 **0.965 – 1.003**，几何平均 **0.982**，全部 `GEMM_OK`。
