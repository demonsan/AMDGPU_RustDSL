# 性能矩阵：出厂 FMHA / GEMM 对厂商内核（同一次运行、交替测量）

FMHA：Main `bf08b7b0`（XCD 感知的 block 顺序 + `wsink` / `ldsink` / bias 修复 / 真实数据分派），MI355X（mi355-gpu-53，**GPU 5**），2026-11-08，**真实数据**（`REF_DATA=normal`）。
GEMM：Main `f2759cd`，GPU 4，2026-11-05（本轮未重测）。脚本：`tools/perf_matrix.sh`（原始输出）+ `tools/perf_matrix_md.py`（表格）；原始逐次数据见 `docs/perf-matrix-raw.txt`。

## 方法

* **硬件 / 时钟**：单卡（FMHA：GPU 5；GEMM：GPU 4）；**未锁频**（功耗墙下的自然时钟）。同板其他 GPU 上可能有别的任务（功耗共享），绝对值有 ±1–2 % 的运行间漂移，比值比绝对值更可靠。
* **交替（interleaving）**：每一次 `ref_host` / `gemm_ref_host` 进程里厂商内核与我们的内核在同一个进程、同一组输入上依次计时（先热身，再各 100 次启动取均值）；
  **重复轮在外层、形状在内层**（5 轮 × 全部形状），所以时钟漂移被均摊到所有形状。每格取 **5 次的中位数**，比值 = 我们的中位数 / 厂商的中位数。
* **FMHA**：热身 150 + 100 次计时（`REF_WARMUP=150 REF_ITERS=100`），`REF_ROWS=1`；`auto` 分发由 `ref_host` 按形状选择，"路径"列是它实际选的内核
  （`t128` = 128 行/块，`vs128` = 256 行/块，`kvsplit` = KV 分裂主核 + combine，计时为 main+combine 的总时间）。TF/s 按 4·B·H·S·SK·128 计算。
* **FMHA 精度**：每个形状另跑一次 `REF_ROWS=64`（64 行 × 128 维对 CPU 模型）：`bad` = 超出绝对容差的元素个数，`mean_err` = 平均误差。≥ 4 个 tile 的序列三条路径都用厂商配方（懒更新），所以 mean_err 与厂商基本相同；更短的序列用精确（LUT 修正）配方。
* **GEMM**：每个形状 5 个进程，每个进程 `REF_REPS=3` × 100 次启动（热身 300）取中位数，再取 5 个进程的中位数；每个进程都做 48 行 × 全部列的双精度 CPU 校验（`GEMM_OK`）。
  形状均满足 M、N 为 256 的倍数、K 为 128 的倍数且 ≤ 8192。
* **FMHA 输入**：`REF_DATA=normal`（N(0,1) 的 Q / K / V，Q 乘 log2(e)/√128，按 32 元素块量化成 MXFP8：E8M0 = floor(log2 amax) − 8，e4m3 舍入到最近偶数；V 按张量一个 f32 descale）。
  harness 的调色板数据（`REF_DATA=lcg`）让 softmax 几乎每个 tile 都回滚，会掩盖快速路径的成本（厂商在真实数据上快约 40 %），所以从这一版起矩阵与 `port_gate` 的 PERF 都用真实数据。

## 摘要

* FMHA（真实数据）：25 个形状比值范围 **0.929 – 1.063**，几何平均 **0.992**（XCD 顺序之前 0.980）。小形状（`t128`）0.99–1.06×；`kvsplit` 0.93–1.05×（GQA 2 / 4 为 0.93×）；
  满载 `vs128` 0.95–1.01×（S ≤ 4096 受益于 XCD 感知的 block 顺序，见 [`fmha-wave-org.md`](fmha-wave-org.md)；S = 8192 保持原顺序，0.95–0.99×）；精度（64 行）全部 `bad=0`，mean_err 与厂商一致。
* GEMM：6 个形状比值 **0.965 – 1.003**，几何平均 **0.982**，全部 `GEMM_OK`。
